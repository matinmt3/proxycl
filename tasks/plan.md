# REVMAMAD 4 implementation and release plan

Approved on 2026-10-23. Baseline: v3.4.0 / 32842eaca407affca222a47899afa52f6fd71364.

Deliver Termux plus a local Persian dashboard. Keep the ordinary scanner account-free.
Optional media testing is terminal-authorized, RAM-only, sequential, two 8 MiB rounds
for up to five fresh qualified proxies, a 100 MiB observed-byte cap and a 600 second
deadline. No direct Telegram network fallback, account data exports, or automatic messages.

## Ordered vertical slices

1. Phone reliability: cross-process output ownership, crash recovery, diagnostic categories,
   preserved user sources/settings, staged updates and rollback.
2. Evidence and ranking: freshness on use/export, versioned policy, interleaved finalist
   rounds and within-session metrics; retain v1 default pending calibration evidence.
3. Sources and daily UI: all memberships, mirror-aware yield, user source management,
   favourites with fresh recheck, three visible groups, Persian RTL and local themes.
4. WEB: pinned official contract, TLS/large-stream/root/base-path conformance, clear
   native-versus-client compatibility evidence.
5. Media beta: isolated Telethon adapter, immutable proxy routing for every DC, no CDN
   fallback, exact limits, separate outcomes/reports, bounded logout and no session files.
6. Integration: backwards-compatible CLI, installed runtime tests, redacted diagnostics,
   full regressions, real browser interactions, release packaging and downloaded hashes.

## Parallel ownership

- Engine: scan/config/models/checkpoints/staged probes/ranking/export/lock/calibration.
- Media: optional media package, packet transport, FakeTLS fragmentation and tests.
- Sources/UI: collectors/source store/favourites/dashboard and tests.
- Root: CLI, doctor/updater/installer, integration, review, docs and release evidence.

## Release gates

Automated and controlled host evidence do not substitute for physical Android, an
authorized account download, real WEB client use, or 18 paired calibration runs across
three days and two networks. Publish a 4.0.0-rc.1 prerelease when implemented local
checks pass; keep v3.4.0 as the latest stable until all required real-world evidence is
recorded. WEB and new ranking remain experimental while their gates are unmet.

Never fabricate active sources, proxy success, device passes or measured throughput.
Changes in schemas retain readable old observations but require new proof where needed.
Before publication independently review route isolation, freshness, locks and updates.
