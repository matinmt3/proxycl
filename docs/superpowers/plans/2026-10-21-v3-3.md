# REVMAMAD 3.3 execution plan

The approved scope improves on-device proxy selection, interrupted scans and source quality while retaining strict server authentication and account-free operation.

1. Add bounded staged scanning: a transport prefilter, strict sessions, then sustained reconnect/ping checks for up to twenty finalists. Transport-only success never qualifies links. Completed runs require the stronger sample policy; stopped runs clearly identify provisional evidence.
2. Save atomic checkpoints after finished samples. Resume uses the same mode, named network and configuration and refuses stale/corrupt state. Old evidence never silently crosses networks or becomes fresh proof.
3. Keep bounded per-network history with timestamps and counts. History informs the user and does not manufacture live verification.
4. Record source retrieval/qualification quality and temporary cooldown after repeated failures. Local manual sources remain available; remote sources are retried after cooldown.
5. Expose stages, progress, resume, network selection and history in the terminal and dashboard. Add a Termux self-check for the user's real phone validation.
6. Run deterministic regressions and bounded live checks, build and retest the ZIP, then publish and verify the public tree, installer, tag and downloaded assets.

The user will execute the phone check in Termux. Physical Android evidence must be reported separately from host simulations. Telegram account login and media download remain a separate, optional future feature.
