# REVMAMAD v3 Implementation Plan

> For agentic workers: use Superpowers task briefs, TDD and independent review. Execute the user-approved update continuously in this session.

**Goal:** Ship independently tested MTProto/Web proxy scans with >=50 sources each, ALL/custom selection, consistent top10 and mobile UI.
**Architecture:** Preserve MTProto transport code. Add isolated webproxy transport and shared scan orchestration. Publish per-mode atomic snapshots for a read-only dashboard.
**Tech stack:** Python 3.12+, asyncio, existing httpx/YAML/crypto/tqdm, standard-library HTTP server and local HTML/CSS/JS.
**Spec:** ../specs/2026-10-08-v3-design.md

## Global constraints

- Preserve user data and old releases; no credential collection or direct-probe fallback.
- >=50 enabled distinct remote feeds per mode, no silent ALL candidate cap.
- Web origin and HTTPS proxy certificate checks stay enabled.
- Same score/latency/key order in all top10 surfaces; isolated output folders.
- Mobile UI is usable at 320 px and without CDNs; physical Android remains an explicit limitation.

## Review focus

- Protocol-specific HTTPS labels can mean HTTP CONNECT; bare endpoints need accurate defaults.
- Source order can monopolize N; selection follows global deduplication/source interleaving.
- Empty/cancelled scans must not overwrite another mode or mislabel old data as new.
- Public invalid/oversized feeds and TLS/HTTP failures must be rejected without aborting healthy work.
- Separate read endpoints must not mix snapshot generations; frontend consumes one snapshot.
