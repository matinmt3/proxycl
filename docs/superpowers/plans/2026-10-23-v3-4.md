# REVMAMAD 3.4 Implementation Plan

> For agentic workers: implement and review the independent protocol, engine and dashboard slices, then integrate and verify the whole release.

**Goal:** Add Telegram's official WEB proxy type and the approved phone-oriented scan improvements to the existing tested CLI/dashboard.

**Architecture:** Preserve the existing MTProto and HTTP/SOCKS modes. Add `webproxy` as a fourth mode with its own canonical link model and relay carrier, then run the same server-authenticated Telegram sessions over that carrier. Keep scan control local, bounded and single-flight; retain finished evidence and remeasure expired evidence before recommendation.

**Tech stack:** Python 3.12+, asyncio, existing httpx/PyCryptodome, standard-library HTTP dashboard, local JavaScript/CSS. No Telegram account credentials.

**Approved scope:** The user accepted the 3.4 roadmap and asked to research and implement WEB proxy. Physical Android verification requires a connected device; host/browser/protocol fixtures must never be represented as a phone pass. Account-authorized media testing belongs to a separate future version.

## 1. Official WEB contract and transport

Files: new `telegram_webproxy/`, `tester/mtproto.py`, configuration/collector/export/state integration, focused WEB contract tests.

- [x] Pin primary server/client sources and distinguish `t.me/webproxy`, ordinary `t.me/proxy` share links and HTTP/SOCKS.
- [x] Model DNS hostname plus optional canonical base path, implicit port 443, raw/dd secrets and path share-link marker. Reject ambiguous/credentialed/malformed links and unsupported inner FakeTLS secrets.
- [x] Derive the capability locally; bootstrap the official relay session and verify the mux WELCOME handshake. Carry the existing MTProxy obfuscated stream through certified WSS and supported HTTPS carriers with bounded frames, flow control, timeout and cancellation cleanup.
- [x] Add `webproxy` mode, configurable/public/manual sources, checkpoint/history/export roundtrips and menu/CLI import support. A public endpoint is not working merely because its site or WSS upgrade responds.
- [x] Test parser/framing/flow-control failures, strict Telegram proof over controlled carrier and upstream local interoperability where available. State that a Python carrier does not reproduce an embedded browser's TLS fingerprint.

Interfaces: `TelegramWebProxy(server, secret, source, tag, port=443)`, `parse_line`, `extract_links`, `open_connection(proxy, timeout=...) -> (reader, writer)`; existing Telegram `verification_profile='telegram_session'` and strict eligibility remain authoritative.

## 2. Bounded and adaptive scan execution

Files: `utils/scan_control.py`, existing testers, loader, `scan.py`, CLI and focused budget/stop/Resume tests.

- [x] Add validated `scan.time_budget_seconds`, `scan.adaptive_workers`, `scan.finalist_reserve_fraction` and CLI `--minutes`. Existing unlimited behavior remains available.
- [x] Use a thread-safe stop controller and bounded adaptive per-attempt slots. Pressure feedback comes from local event-loop lag, not an assumption that failed remote proxies imply CPU pressure.
- [x] Reserve time for finalists after screening/baseline admission. On budget exhaustion retain only finished samples, report actual coverage and provisional status, and keep the full candidate pool resumable.
- [x] Resume frozen unfinished finalists first; a completed timebox can continue pending candidates without replaying completed samples or manufacturing failed attempts.
- [x] Test deadlines and external stop at each stage, repeated timeboxes, native CLI cancellation, worker bounds and telemetry.

Interfaces: engine `ScanController.request_stop(reason)`, `.stop_requested`, `.reason`; tester optional `controller` keyword; summary records budget/coverage and effective worker changes.

## 3. Refresh expired evidence on Resume

- [x] Load the saved candidate pool under the same mode/network/configuration guards and bounded retention; keep strict `.load()` age behavior for direct callers.
- [x] Identify expired finished observations, remove expired evidence and screen decisions, rebuild current policy and rerun the affected candidates. Preserve only still-fresh finished evidence.
- [x] Reset engine phase/finalist state coherently; keep run identity/history idempotence and record refresh counts. Future/corrupt/mismatched/complete checkpoints still fail.
- [x] Prove that stale scores/samples cannot qualify links and JSON/large-Web SQLite both retain candidate identity/order.

## 4. Local dashboard controls and useful explanations

Files: `dashboard/control.py`, server/app/data/client/assets, `main.py` and focused API/client tests.

- [x] Add start, stop, resume and recheck controls, network/count/time inputs and explicit Scan versus Recheck Resume selection.
- [x] Allow only a single owned job; invoke a whitelisted Python callback without shell strings. Limit JSON request size and validate action/mode/network/count/minutes.
- [x] Keep mutations loopback-only, validate Host/Origin, require an unpredictable local token in a header, and reject cross-site requests. Read-only dashboards remain compatible.
- [x] Show four unambiguous mode labels, provisional/coverage/pressure feedback and plain-language qualification/failure explanations. Historical data never becomes fresh proof.
- [x] Verify keyboard/touch/status behavior, 320/390-pixel layouts and real start/stop/Resume against local controlled fixtures.

Interface: `dashboard.control.ScanController(config, execute)` invokes `execute(config, mode, limit, command, resume, stop_event)`. `create_server(..., controller=None)` preserves read-only defaults. POST `/api/control` uses explicit actions and a local token, never arbitrary commands or file paths.

## Review focus

- A WEB relay HTTP response or WSS upgrade must never substitute for RSA/DH and encrypted Telegram pongs.
- Base-path share-link marker and capability derivation must roundtrip without sharing the raw secret with fetched JavaScript.
- A stopped/expired/time-limited result must not bypass the current success/DC/ping policy.
- Local browser controls must not permit cross-site job creation or arbitrary command execution.
- Candidate preservation must not preserve expired live eligibility, including large SQLite pools.
