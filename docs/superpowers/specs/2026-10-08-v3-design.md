# REVMAMAD v3 approved design

The user approved the presented design on 2026-10-08 and instructed implementation, testing, repair and publication. This document records that brief and the concrete interfaces. Execution continues in this session with delegated independent components.

## Outcome and platform

Termux users choose MTProto or Web Proxy independently. Each scan offers ALL or a custom positive number of candidates, then displays up to ten verified eligible results. Retain the REVMAMAD ASCII banner. Improve the terminal and the read-only mobile dashboard without a frontend build tool or CDN dependency. Python 3.12+ and the lightweight standard-library dashboard remain supported.

## Sources and selection

Ship at least 50 enabled, distinct remote source URLs for each mode, sourced from the researched catalogs. Distinct feeds are not necessarily independent publishers or currently available. MTProto default proposal: 60 feeds (54 channel identities and 6 GitHub content families). Web defaults: 64 content-distinct protocol feeds. Do not count empty files or an exact normalized mirror to pad totals.

Keep existing YAML `sources` as MTProto. Add `web_sources` and optional `source_catalog` pointing to a YAML mapping containing the two lists. Explicit lists override their respective catalog lists, including an explicit empty list. Source locations and output/log paths resolve from the config's base. Add `WebSourceConfig(name,type,url,protocol='http',enabled=True)`; protocol is http/https/socks4/socks5. A bare endpoint in an HTTPS-capable HTTP feed uses http; explicit https:// means TLS to the proxy.

Collectors expose `.source_reports`, each a dict with name, status (ok/empty/error), count and optional safe error class/status. Retain 4 MiB per-source download bounds, eight concurrent source reads and bounded test workers. Collection errors do not abort other sources. Globally deduplicate, then interleave source groups deterministically before selecting at most N. ALL means every collected valid unique candidate; no hidden testing cap. N limits candidates, not retries or top10 size. If N exceeds supply, report the smaller selected count.

## Protocol verification

Retain raw/dd/ee MTProto nonce-matched resPQ checks. Add an isolated webproxy package: WebProxy, parser/collector, transport probe, bounded tester and exporter. WebProxy exposes server, port, protocol, source, key(), to_dict() and uri(). Shared ProxyResult metrics/scoring may be reused; web serialization must never invent Telegram secrets/links.

HTTP uses CONNECT for an HTTPS origin; HTTPS first negotiates certificate-verified TLS with the proxy; SOCKS4 uses SOCKS4a hostname routing; SOCKS5 negotiates unauthenticated CONNECT. All then negotiate certificate-verified TLS with the origin and validate its bounded HTTP response. Default origin: https://www.gstatic.com/generate_204, expected status 204. No direct fallback, no TCP-only success, no disabled certificate validation. Credentials are excluded from public feeds in this release. A test success establishes reachability to this origin, not all websites.

`WebCollector(config).collect() -> list[WebProxy]`, `.source_reports -> list[dict]`; `WebTester(config).run(proxies) -> list[ProxyResult]`; `WebExporter(output_cfg).export_all(results)` and `.export_best_n_readable(results,n=10)`. Reuse existing worker_count() and TestSample where appropriate. Timeout and cancellation close connections.

## Orchestration, ranking and exports

`scan.run_scan(config, mode='mtproto', limit=None, export=True) -> ScanOutcome`. Outcome fields: results, eligible, top, summary, source_reports, folder. A positive integer limit is validated before network work. `select_candidates(proxies, limit)` deduplicates/interleaves before testing.

Rank composite score descending, latency ascending, stable endpoint key as the final tie breaker. Console, readable file and top10.json use identical top ten eligible results; display fewer when fewer pass. Output folders are `<output>/mtproto` and `<output>/web`. A completed empty scan clears only its mode. Cancellation preserves the previous completed snapshot.

Atomic `snapshot.json` schema: {version:1,mode,summary,source_reports,rows}. Summary keys: started_at,completed_at,requested_count (null means ALL),collected,selected,tested,verified,eligible,displayed,failure_counts. Rows contain eligible results in common ranking order. Summary and rows are read from one snapshot generation. Failed scans must not claim a new completed scan. Retain compatibility wrappers for old MTProto commands, now writing the mode folder.

## Terminal and dashboard

Menu: 1 MTProto test, 2 Web Proxy test, 3 Dashboard, 4 Collect candidates (choose mode), 5 Exit. Each test opens a sub-menu 1 ALL / 2 Custom count / 0 Back. Invalid input retries, EOF exits cleanly, Ctrl+C returns from scans. Direct CLI adds `--mode mtproto|web` and `--count ALL|N`, preserving existing commands/help/version/lazy imports. Test commands show collecting, selected count, progress, failure counts and up-to-ten results.

Read-only dashboard: local assets/system fonts, dark opaque panels, REVMAMAD brand, distinct mode selector, snapshot time, selected/tested/verified/displayed counts, source health, labeled search/sort, web protocol filter, result cards at phone width, copy URI and Telegram connect. Minimum 44 px touch targets, visible focus, text contrast >=4.5:1, reduced motion and no page-wide horizontal overflow at 320 px. Refresh/pause controls; polling pauses when hidden. Clear no-scan/empty/filter-empty/stale/corrupt states. Safe text rendering and validated links.

Keep `/api/proxies` and `/api/stats` defaults for MTProto compatibility; add `/api/snapshot?mode=mtproto|web` returning a single validated snapshot, optional legacy MTProto fallback marked time unknown. stdlib server and optional FastAPI adapter share mode selection/data logic. No scan-start/job API is introduced.
